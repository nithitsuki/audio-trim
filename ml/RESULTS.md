## Error analysis (from `reports/errors_*_heldout.csv`)

1. **Unseen slang verbs beat the rules.** "nuke", "chuck", "lose", "erase", "no more" fall through to no operation. Context (`vocals`, `drums`) rescues some, not all.
2. **Cut vs trim is hard without a keep/delete cue.** "keep 0:10 through 0:50" and "leave only 30 seconds starting at 1:00" confuse both models.
3. **Speaker canonicalisation is a rule win.** "I only need the host" means remove speaker 2. The learned model maps "host" to speaker 1, wrong polarity.
4. **Numbers do not transfer.** The TF-IDF regressor predicts the mean for unseen
   bpm values, and bag-of-words cannot represent magnitude. This is a
   representation problem, not a tuning problem. Fix directions: numeric tokens,
   a number-extraction step, or digit-aware tokenization. Evaluate on more rows.
5. **Ambiguous instructions stay hard.** "make the kick drum punchier by 3 db" is a gain because of the number. The model sometimes picks `add_effect`.

The model is **not usable yet**. Per-class thresholds tuned on the small
validation split make it over-predict operations, and bert-tiny is too small for
622 training rows. For real numbers, use DistilBERT or similar on ≥1,000
hand-checked prompts and tune thresholds on validation only. The script is ready:

```powershell
# Colab / Kaggle / GPU host
python scripts/train_transformer.py --model-name distilbert-base-uncased `
  --epochs 5 --lr 3e-5 --batch-size 16
# evaluate a checkpoint on either split
python scripts/evaluate.py --split test `
  --transformer-preds models/transformer/test_predictions.json
python scripts/evaluate.py --split heldout `
  --transformer-preds models/transformer/heldout_predictions.json
```
